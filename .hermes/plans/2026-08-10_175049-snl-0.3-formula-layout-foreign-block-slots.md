# SNL 0.3 Formula Layout and Foreign Block Slots Research Plan

**Status:** Architecture proposal only; do not implement in 0.2.1.

**Goals:**

1. Decide whether `formula_display` can be deprecated in favor of an explicit built-in display wrapper.
2. Prototype HTML/React block descendants inside KaTeX-owned formula layout while preserving one surrounding KaTeX render.

## Current facts

- `formula_display` has one runtime distinction from `formula_inline`: when it is the root of a KaTeX render call, `nodeDisplay(...)` sets `katex.displayMode = true`.
- Nested `formula_display` under an already-formula ancestor is treated exactly like `formula_inline`.
- Formula children reached from text/block are separate `MathSpan` roots, so their own `formula_display` still has effect.
- No real Macro record in the Basics repository uses `formula_display`; current occurrences are schemas, docs, migration fixtures, UI support, parser `$$...$$`, and tests.
- KaTeX `displayMode=true` changes both wrapper/layout and TeX mathstyle. A real probe showed `\sum` uses `op-limits` in display mode, not inline mode.
- Inline `\displaystyle{...}` reproduces display mathstyle but not the `.katex-display` wrapper.

## Recommendation for `formula_display`

### 0.2.1

Keep it. Removing it now would be schema/API churn immediately before publication and would change `$$...$$` and old `display=block` migrations.

### 0.3.0 candidate

Separate renderer backend from layout:

```ts
type Mode = 'formula' | 'text' | 'block'
type FormulaLayout = 'inline' | 'display'
```

Or make display explicit in the syntax tree through a built-in structural wrapper:

```text
Display(formulaChild)
```

The built-in `Display` implementation would:

1. create a React block boundary;
2. center or otherwise align the child;
3. render the child in a separate KaTeX root;
4. force display mathstyle, either with `displayMode=true` or `\displaystyle`.

A pure inline promotion macro (`\displaystyle{#0}`) is insufficient: it changes mathstyle but cannot create a block/line boundary inside an existing KaTeX formula.

A centered block plus promoted formula covers current visual needs if equation tags, `fleqn`, `leqno`, and exact `.katex-display` behavior are not required. It is not a universal semantic replacement for KaTeX display mode.

### Migration gate

Before deprecation:

1. audit real consumer Macro10 data, not only repository fixtures;
2. add `Display` and migrate `formula_display` to `Display(formula_inline(...))` in a reversible prototype;
3. compare browser geometry, mathstyle, selection/copy, hover metadata, and export output;
4. explicitly decide support for tags/equation numbering/fleqn;
5. keep parsing `$$...$$` as sugar even if persisted representation changes.

## Foreign block inside formula

### Rejected naive design

Do not render KaTeX, mutate a `\phantom` marker's CSS size, and replace its children with a live block.

A real Chromium/KaTeX probe used `\htmlData{slot=...}{\rule{20px}{20px}}`, then changed the marker to 120×60 px:

- ordinary inline flow partially expanded, but the `.katex` box stayed 21 px high and the slot overflowed;
- inside a fraction/vlist, the fraction layout did not expand and the slot overflowed by about 72 px.

KaTeX computes vlist/strut geometry during render. Post-render CSS mutation cannot reliably repair those explicit dimensions.

### Feasible architecture: measured foreign-box slots

Keep one surrounding KaTeX formula, but treat each block descendant as a foreign replaced atom.

#### 1. Stable external React layer

Mount every block renderer once in a React overlay/staging layer outside KaTeX-owned `innerHTML`. Do not portal the live block directly into a KaTeX span: each KaTeX rerender destroys the target and would reset widget state.

Each slot has a stable ID derived from the syntax-tree path and render generation.

#### 2. Measure before KaTeX layout

Render the live block hidden/offscreen under a known width constraint. Measure:

```ts
interface ForeignBoxMetrics {
  width: number
  height: number
  depth: number
  baseline: 'alphabetic' | 'axis-center' | 'bottom'
}
```

Initial v1 should support intrinsic/fixed width only. `fill` or self-dependent wrapping introduces circular layout.

#### 3. Emit sized KaTeX placeholders

During LaTeX resolution, emit a trusted marker with dimensions already known:

```tex
\htmlData{snl-slot=<id>}{\rule[<shift>]{<width>}{<height>}}
```

The exact rule/raise encoding needs a KaTeX metric calibration test; CSS px values observed in output are not assumed to map 1:1 without verification.

Because dimensions are present when KaTeX builds vlists, fraction/matrix/array ancestors can reserve the correct box.

#### 4. Position the live HTML block

After KaTeX commit:

1. locate `[data-snl-slot="id"]`;
2. read its viewport geometry;
3. place the persistent live block in an absolutely positioned overlay relative to the shared render host;
4. keep placeholder content invisible but layout-active;
5. route pointer/focus events through the existing SNL interaction model using the same `data-tree-path`.

#### 5. Dynamic size changes

Attach `ResizeObserver` to each live block. Batch metric changes in one `requestAnimationFrame`:

1. update metrics when delta exceeds 0.5 px;
2. rerender the surrounding KaTeX root with new sized placeholders;
3. remap marker geometry;
4. move overlays without remounting the block subtree.

Use maximum four convergence iterations per frame/update epoch. Detect oscillation and fail visibly to an out-of-formula block fallback rather than loop forever.

### Required policies

A generic `block` mode is too underspecified for formula embedding. Add explicit foreign-box policy:

```ts
interface FormulaEmbedPolicy {
  width: 'intrinsic' | { px: number } | { max_host_width: true }
  baseline: 'alphabetic' | 'axis-center' | 'bottom'
  overflow: 'visible' | 'clip' | 'fallback-block'
  accessible_text?: string
}
```

Recommended defaults:

- icon/badge: intrinsic + alphabetic/axis-center;
- chart/widget: intrinsic/fixed + axis-center;
- enumerate/table: max-host-width + axis-center or fallback-block.

### Hard problems

1. **Circular width:** wrapped enumerate/table width may depend on available formula width, while formula width depends on the slot.
2. **Baseline/depth:** DOM does not expose a general element baseline; policy must define it.
3. **Accessibility:** overlay DOM is not naturally located at the placeholder's reading-order position. Require accessible fallback text and test screen-reader tree/order.
4. **Selection/copy:** KaTeX text and overlay content are separate DOM ranges.
5. **Scrolling/transforms/zoom:** marker-to-overlay mapping must react to scroll capture, resize, visual viewport, and host transforms.
6. **Nested formulas:** a block can contain formula children, producing nested KaTeX roots; generation and tree-path routing must remain unique.
7. **SSR/static export:** no measurement exists. Require precomputed metrics or render a visible stacked fallback.
8. **Performance:** N slots plus dynamic widgets can cause whole-root KaTeX rerenders. Batch and cap updates.
9. **Focus preservation:** the external live subtree must never remount solely because KaTeX rerendered.
10. **Trust boundary:** only Basics-generated slot IDs/dimensions enter trusted KaTeX commands; authored templates cannot inject arbitrary HTML/style.

## 0.3 milestone proposal

### Spike A: static one-slot atom

- one fixed 32×32 icon inside `a + slot + b`;
- placeholder emitted before KaTeX render;
- external overlay aligned to marker;
- no dynamic resize.

### Spike B: vlist ancestry

Test the same slot inside:

- fraction numerator and denominator;
- square root;
- superscript/subscript;
- matrix/array cell;
- `\sum` limits;
- nested delimiters.

Reject the architecture if marker and overlay cannot remain aligned under these structures.

### Spike C: dynamic widget

- persistent interactive chart changes size repeatedly;
- ResizeObserver triggers batched KaTeX rerender;
- focus and internal React state survive;
- convergence and oscillation guard verified.

### Spike D: true block content

- enumerate with formula children;
- table with dynamic rows;
- nested block→formula→foreign block;
- hover/click/pin behavior and tree paths;
- accessibility and copy behavior.

### Production gate

Only promote after real Chromium geometry tests, screenshot regression, mutation checks, clean packed-consumer test, Extension real Entry integration, and a documented static-export fallback.

## Decision

- `formula_display`: useful but narrowly scoped; keep for 0.2, reconsider/decompose in 0.3.
- built-in inline promotion alone: insufficient.
- centered Display block + display mathstyle: likely enough for current visual needs, subject to tag/fleqn requirements.
- dynamic foreign block slots: feasible as a 0.3 research feature with premeasurement + KaTeX rerender + persistent overlay; the simple post-render phantom replacement idea is not robust.
